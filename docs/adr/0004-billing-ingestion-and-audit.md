# 0004 一期计费入库与运营追溯

状态：已采纳 · 日期：2026-11-12 · 相关任务：[#4](https://github.com/DuanJinTaoToday/proxy/issues/4)、[#7](https://github.com/DuanJinTaoToday/proxy/issues/7)、[#14](https://github.com/DuanJinTaoToday/proxy/issues/14)

## 背景

[ADR 0001](0001-usage-data-model.md) 和 [ADR 0003](0003-reporting-and-usage-contracts.md) 已确定按记录时间计费、以文件水位去重及按聚合复核用量。一期入库还需要明确跨到期补报、分组变更、偏移缺口与来源隔离的处理。运营需要独立的计费写权限，并能按倍率版本核对汇总和定位原始文件。

## 决定

### 1. 晚到记录与授予到期

- 按 `starts_at <= recorded_at < expires_at` 选择记录发生时有效的授予，无到期时间视为无上界。按 ADR 0001 的顺序分配，最多扣减入库时尚未消耗的额度，超出部分按原规则分配或记为欠费。当前已到期的授予仍可用于其有效期内的补报。
- 入库和到期任务共用租户额度锁。到期任务按授予幂等补记 `grant_expire`。若先入库，任务按扣减后剩余量记失效。若先记到期流水，补报在同一入库事务追加 `grant_expire_correction`，关联原流水，`delta_bytes` 等于本次从已到期授予扣减的正数字节数。冲正只修订净失效量，冲正自身的 `available_before` 与 `available_after` 相同。用量、授予已用量、冲正和水位一起提交。
- 例如，授予到期时记失效 100 字节，之后收到到期前的 30 字节，计费汇总和授予已用量各增加 30，冲正记 `+30`，净失效量为 70。准入始终排除已到期授予。
- 未来生效的授予创建时记录充值或补增，生效前既不抵扣欠费，也不进入可用额度。生效时在租户额度锁内先按当时欠费执行一次抵扣并记录 `overdraft_offset`，余量才可用于准入。余额读取和分配在使用该授予前确保生效抵扣已完成。即时生效的授予仍在创建事务内抵扣。缓存最迟在相关授予的生效或到期边界失效。

### 2. 租户分组归属版本

- `tenant_group_members` 改为按 `(tenant_id, effective_from)` 保存只追加的归属版本。每次设置或清除分组均从本次变更时点生效，清除以空 `group_id` 表示。没有历史版本时视为未分组。并发变更按租户串行，保证生效时间有确定顺序。
- 计费先按 `recorded_at` 选择最近已生效的归属，再按租户、该分组、全局的优先级选择当时生效的倍率版本。12:00 从 A 组迁到 B 组时，11:59 的记录即使 12:05 才入库也用 A 组。已入库汇总不重算。准入门槛和提醒阈值使用当前归属。

### 3. 文件水位连续性

- `RecorderLine` 增加 `uint64 end_offset = 4`，表示分隔符之后的第一个源文件字节。记录区间为 `[file_offset, end_offset)`。采集器以原文件字节计偏移，包含实际行分隔符，只发送完整行。控制面校验区间长度等于原始行的 UTF-8 字节数加分隔符字节数（LF 为 1，CRLF 为 2）。`line` 仍不带分隔符。
- 每个新文件的水位从 0 开始。批内按源文件顺序逐条检查，整个区间已确认的记录跳过。首条新记录及其后每条记录的起点必须等于该文件当时的水位。起点高于水位、区间跨越水位或偏移非法时，整批回滚并返回 `400 INVALID_BATCH`，采集器保留文件并告警。
- 连续的完整行无论计量、不计量还是隔离，都把水位推进至该行的 `end_offset`，批次提交后才确认。水位元数据须覆盖文件可重放期间。

### 4. 用量来源与归档后补报

- 在 `usage_minutely` 与 `usage_daily` 增加非空 `source`，纳入两表主键及归档分组。隧道入库写 `tunnel`。查询默认限定 `tunnel`。提取 Mock 使用独立的 `api_extraction_mock` 来源，只有显式选择该来源时才返回，具体查询字段随 #8 定义。按网关筛选或拆分时，Mock 没有关联的网关。
- Mock 仅验证提取和用量查询归属，产生的模拟用量不参与真实授予、欠费、可用额度和额度对账。真实 API 提取的扣减规则随供应商接入另定。
- 分钟汇总保留 60 天。已归档的上海自然日收到补报时，直接累加同一来源的日汇总，扣减与推进水位仍在同一事务。入库与归档按日期共用串行边界，防止并发漏计或重复累加。

### 5. 计费管理权限

- `bootstrap.proto` 的用户配置增加 `bool manage_billing = 5`，默认关闭。原有 `platform_operator: true` 继续授予 `PERMISSION_READ_OPERATIONS`。仅当两个开关都为真时授予 `PERMISSION_MANAGE_BILLING`。非平台运营配置 `manage_billing: true` 时拒绝启动。
- 计费写接口要求 `PERMISSION_MANAGE_BILLING`，计费读接口接受 `PERMISSION_READ_OPERATIONS` 或 `PERMISSION_MANAGE_BILLING`。一期沿用启动配置变更后重启生效的方式。

### 6. Recorder 文件追查与保留

- 控制面的运营查询提供定位信息。经授权的运维人员通过有审计记录的主机访问，在对应网关以只读方式按 `gateway_id`、`boot_id`、时间范围，以及已有的 `file_id`、`file_offset` 检索 Recorder 文件。控制面无需挂载文件，也不提供下载原始记录的接口。网关文件访问权限独立于控制台运营权限。
- 文件关闭且所有记录获得入库确认后，至少保留 14 天供追查。保留期届满后，只有控制面已确认该启动代次完成缺口核对，或采集器已持久化该文件中核对所需的证据，才可清理。未确认文件继续保留，磁盘压力触发告警。
- 缺口核对尚未完成时，采集器须在删文件前持久化证据。证据按启动代次保存，采集器重启后仍能与剩余文件合并，判断每个会话是否出现 `final`，并恢复缺少 `final` 的会话 ID、`client_id` 和最后采样时间。证据保留到控制面确认该代次缺口核对完成。

### 7. 按倍率版本复核

- `QueryUsageRequest` 增加 `bool split_by_rate = 10`，`UsageBucket` 增加 `string rate_id = 5`。开启时按入库保存的倍率版本分桶并返回该版本 ID，可与网关、授予拆分组合。关闭时合并倍率版本，`rate_id` 为空。分钟、小时和日粒度均支持，键集分页和日归档均保留拆分维度。运营可按 `rate_id` 与倍率版本列表核对。

| ADR 0001「额度」「入库事务」「充值、调整与准入」 | 将定时到期说明中结算排除过期授予的判定基准明确为记录时间，入库锁定可被本批使用的历史授予。补充到期冲正。新授予在生效时抵欠，即时生效时仍在创建事务抵扣。 |

## 备选方案

- 到期后把历史补报一律计为欠费，会让相同记录因控制面停机而改变授予归属。等待所有网关补齐才记到期，会推迟到期对账。追加冲正允许独立到期和补报。
- 用入库时分组解析倍率会让历史计费依赖到达顺序。保留归属版本增加少量配置数据，可直接复核晚到记录。
- 只用起始偏移去重会把跳报变成永久缺口。连续区间校验使缺口在确认前可见。
- Mock 复用真实额度会污染准入和对账。把运营读写绑定同一开关会给已有账号授予写权限。集中读取网关目录会引入跨主机文件访问和原始记录暴露面。

## 影响

- #4 验证晚到跨授予到期及跨日归档、分组变更前后补报、连续与跳跃偏移、整批失败及重放去重。包含隔离坏行后连续推进、到期任务先于及晚于补报两种顺序。
- #7 验证倍率版本与其他维度组合拆分、归档前后汇总一致，以及按运营查询定位信息在授权网关追查样本。清理验收覆盖轮转文件届满 14 天、代次尚未完成核对且缺口证据尚未持久化时保留文件，以及证据持久化后清理文件、重启采集器、再模拟 GOST 异常退出时仍能正确区分缺少 `final` 和已有 `final` 的会话。
- #14 验证未来授予生效前后的抵欠与准入、到期冲正对账，以及普通成员、只读运营和计费运营的权限差异。
