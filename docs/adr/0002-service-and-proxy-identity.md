# 0002 网关服务身份、代理凭据与控制台会话

状态：已采纳 · 日期：2026-11-11 · 相关任务：[#3](https://github.com/DuanJinTaoToday/proxy/issues/3)、[#4](https://github.com/DuanJinTaoToday/proxy/issues/4)

> 认证部署与准入时效的现行约定见 [ADR 0005 一期代理认证可用性](0005-proxy-auth-availability.md#取代条款)。

## 背景

控制面要分别校验三类调用方：网关侧采集器上报批次，GOST 认证插件校验代理凭据，控制台用户查询和管理。三者不得互相冒充，网关之间也不得冒充。01 已实现控制台登录，成员关系来自启动配置，会话令牌由进程内随机密钥签名，有效期八小时。

GOST `v3.3.3` 的 HTTP 认证插件向配置的地址 `POST` JSON `{service, username, password, client}`，期望 `200` 和 `{ok, id}`。插件配置的 `token` 会作为 `Authorization: Bearer <token>` 随每个请求发送，非 `200` 响应视为认证失败。 [go-gost/x v0.28.1 认证插件](https://github.com/go-gost/x/blob/v0.28.1/auth/plugin/http.go) · [插件 HTTP 客户端](https://github.com/go-gost/x/blob/v0.28.1/internal/plugin/plugin.go)

## 决定

### 网关服务身份

- 每个网关实例由运营预置，并签发两个独立的随机令牌，至少 32 字节，以 base64url 交付一次。`report` 令牌供采集器上报批次，`auth` 令牌写入 GOST 认证插件的 `token` 配置。两个令牌只能访问各自的接口。
- 控制面只保存令牌的 SHA-256，按哈希查找 `gateway_tokens`，由令牌确定 `gateway_id`。请求体里的 `gateway_id` 必须与令牌所属网关一致，否则拒绝。网关停用或令牌吊销后立即拒绝。
- 轮换时先签发新令牌，部署后再吊销旧令牌。同一网关同一范围最多两个有效令牌。
- 控制面对网关开放的入口使用 HTTPS，由部署入口终止 TLS。服务令牌与控制台会话令牌使用不同的校验路径，控制台令牌不能调用网关接口，反之亦然。

### 代理凭据

现行认证可用性约定见 [ADR 0005 一期代理认证可用性](0005-proxy-auth-availability.md#取代条款)。

- 租户管理员发放凭据时，控制面生成用户名和至少 128 位熵的随机密码，密码只在发放响应中返回一次。用户名带可读前缀和随机部分，全局唯一。
- 密码以 SHA-256 保存。密码由控制面随机生成且熵足够高，不需要 PBKDF2 这类慢哈希，避免每个新 SOCKS5 连接消耗大量 CPU。比较使用常数时间。
- 发放时可设到期时间和来源地址白名单（CIDR 列表），参照 new-api API Key 的到期时间和 IP 白名单。到期或来源地址不在白名单内时拒绝认证。白名单按 GOST 认证请求中的 `client` 地址判断。
- 认证成功返回该凭据的 `client_id`。停用后新的认证立即失败，已建立的连接不受影响。`client_id` 与租户的映射不可修改，见 [ADR 0001](0001-usage-data-model.md)。
- 认证同时执行租户额度准入，规则见 ADR 0001，接口见 [ADR 0003](0003-reporting-and-usage-contracts.md)。
- 凭据校验结果是否缓存、控制面不可用时如何处理，属于待定的认证可用性设计，本 ADR 不决定。

### 控制台会话

- 一期沿用 01 的实现：成员关系由启动配置加载，变更后重启生效；会话令牌由 HMAC-SHA256 签名，有效期八小时；不提供单个令牌的主动吊销，停用成员通过修改配置并重启生效。
- 一期控制面按单实例部署。部署多个实例前，签名密钥改为从受限访问的部署配置文件读取，所有实例共享同一密钥，并支持新旧两把密钥并存以便轮换。
- 成员关系在出现成员自助管理需求时迁入数据库，届时补充租户与成员表，并在 `proxy_credentials.tenant_id` 等列上补外键。

## 备选方案

- **mTLS 网关身份。** 身份更强，但需要证书签发、分发和轮换流程，GOST 插件也需额外配置客户端证书。一期网关数量少，逐实例令牌加 HTTPS 已能区分实例，后续可在同一 `gateway_id` 上换成证书。
- **采集器和认证插件共用一个令牌。** 配置更简单，但任一进程泄露令牌即可同时伪造用量和探测凭据。两个令牌的额外成本很低。
- **控制台使用 JWT 或服务端会话表。** 01 已实现的签名令牌满足一期单实例需求，引入会话表或 JWT 库可等到需要主动吊销或多实例时再做。

## 影响

- 02 实现凭据发放、停用和 `POST /v1/gateway/auth`，接口形态见 [ADR 0003](0003-reporting-and-usage-contracts.md)。
- 03 实现网关令牌校验中间件和运营预置网关的方式。一期可以用一次性管理命令写入 `gateways` 和 `gateway_tokens`，不提供控制台界面。
- 网关整包交付配置模板，实际令牌从受限访问的部署 YAML 读取。
