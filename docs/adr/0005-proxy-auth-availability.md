# 0005 一期代理认证可用性

状态：已采纳 · 日期：2026-11-12 · 相关任务：[#3](https://github.com/DuanJinTaoToday/proxy/issues/3)、[#5](https://github.com/DuanJinTaoToday/proxy/issues/5)、[#10](https://github.com/DuanJinTaoToday/proxy/issues/10)、[#14](https://github.com/DuanJinTaoToday/proxy/issues/14)

## 背景

控制面一期单实例部署，网关可与控制面分机。短时停机或链路中断会影响新 SOCKS5 连接。已有连接通常持续 2～6 分钟。业务给出的压测输入是每秒 2 万以上新连接，单网关掉线后客户端会在 3 秒内集中重试。

原版 GOST `v3.3.3` / `go-gost/x v0.28.1` 在每次 SOCKS5 用户名密码认证时调用 HTTP 插件，超时、连接失败、最终非 200 响应或 `ok: false` 均拒绝。插件不缓存，`authers[].plugin.timeout` 是 HTTP 客户端总超时，默认值为 0。 [版本依赖](https://github.com/go-gost/gost/blob/v3.3.3/go.mod#L5-L9) · [SOCKS5 认证](https://github.com/go-gost/x/blob/v0.28.1/handler/socks/v5/selector.go) · [插件配置](https://github.com/go-gost/x/blob/v0.28.1/config/parsing/auth/parse.go) · [HTTP 插件](https://github.com/go-gost/x/blob/v0.28.1/auth/plugin/http.go) · [HTTP 客户端](https://github.com/go-gost/x/blob/v0.28.1/internal/plugin/plugin.go)

## 决定

### 1. 离线准入

- 控制面短时不可用时，已预热的网关用有效缓存判断新连接。凭据和租户额度必须都有效。各自从上次有效同步起最多使用 30 秒，刷新失败不续期。缺失、过期或网关 Go 进程重启后无法重新加载时拒绝。多网关各自判断，一期不做故障迁移。
- 网关额度只用于准入。已建立连接继续转发和写 Recorder，控制面按记录时间幂等扣减。按网关独立恢复时，接受其他网关尚未补报的用量仍未反映在租户额度中。
- 30 秒限制的是使用旧状态接纳新连接的时间。额外流量取决于租户吞吐、采样与入库、额度刷新、跨网关积压和已有连接的后续流量。连接在窗口结束前通过后仍可持续产生流量，因此一期没有欠费字节硬上限。

### 2. 部署与认证入口

- 网关整包继续包含原版 GOST 和 `proxy-gateway`。在同一个 `proxy-gateway` Go 进程内按模块实现认证中继与 Recorder 采集器。GOST 只配置一个已注册的 HTTP 认证器，调用 loopback 上的 `POST /v1/gateway/auth`，沿用 ADR 0003 的请求与 `{ok, id}` 响应。启动验收检查引用的认证器实际存在，固定版本的注册表对未注册名称可能返回成功与空 ID。 [GOST 注册表](https://github.com/go-gost/x/blob/v0.28.1/registry/auther.go#L15-L37)
- 控制面提供网关认证状态的按需加载和批量刷新。控制面进程内的可用额度缓存仍按 ADR 0001 和 ADR 0004 维护，入库、充值、调整和相关配置变更提交后刷新或失效。控制面不可用时由网关内存状态承担短时准入。

### 3. 缓存与单次判定

- 凭据按全局唯一的 `username` 索引。数据库约束 `UNIQUE (username)`，发放遇到冲突重新生成。停用保留原记录，重新发放使用新用户名。缓存包含 SHA-256 密码校验值、状态、到期时间、来源 CIDR、`tenant_id` 和稳定 `clientID`。额度按 `tenant_id` 缓存，含可用额度、准入门槛和有效期。
- 每次认证重新检查状态、常数时间比较密码校验值、检查凭据到期、当前请求来源与额度。可用额度低于门槛时拒绝。成功返回凭据的稳定 `clientID`。不缓存单次认证结果或失败结果。

### 4. 刷新、失效与恢复

- 状态按需加载，活跃状态每秒批量刷新。凭据停用、来源策略变更和额度变化收到有效更新即生效，旧状态最多保留至上次有效同步后 30 秒。凭据按自身到期时间直接失效，额度快照不得跨过相关授予的已知生效或到期边界。正常情况下，已提交的余额变化由下一次成功刷新带到网关。
- 认证同步中断、Recorder 批次提交失败，或完整记录待上报超过 5 秒时，停止延长额度缓存有效期。即使认证状态接口还能访问，也不能以未追平的余额续期。没有待上报记录时无需发送空批。
- 恢复通信时，为本机待补报的各文件记录最后一条完整记录的 `end_offset` 作为固定截点。每个文件的连续确认水位达到截点后，才重新读取已提交的额度并恢复续期。使用现有整批提交确认，包括幂等重发确认。截点之后的记录继续按正常流程上报。追平期间旧缓存仍受原截止时间约束。水位只覆盖已写出的完整记录，未采样的流量仍有正常滞后。

### 5. 超时与观测

- 初始配置为 GOST `plugin.timeout: 500ms`，中继冷加载或单次批量刷新总超时 200 ms。一次认证内不自动重试冷加载。同一凭据的并发冷加载合并，每个请求仍独立比较自身密码和来源。一次密码错误导致的冷加载失败仅用于该次尝试。控制面请求处理目标 P99 ≤ 50 ms，在约定批次上限下验收。本机缓存命中路径目标 P99 ≤ 5 ms。生产参数以目标环境压测确定。
- 按网关记录认证成功、业务拒绝和系统失败的计数、比例与延迟。本机命中、冷加载、批量刷新和 SOCKS5 建连分别观察延迟分位数，网关侧探测覆盖请求未到达中继的失败。分别统计凭据与额度缓存的命中、缺失、过期，以及离线放行数、最老未确认记录等待时间和恢复追平耗时。指标标签使用有限的结果类别。

### 6. 密码与服务身份

- 缓存只驻留内存，不保存明文密码。密码仅用于处理当前请求，日志和指标不记录密码、校验值或令牌。
- GOST 用独立本机令牌访问仅监听 loopback 的中继。中继通过 HTTPS 使用 ADR 0002 的逐网关 `auth` 令牌加载与刷新，采集器继续使用独立的 `report` 令牌。网关从部署 YAML 读取令牌并渲染 GOST 模板。
- 冷加载只有在控制面验证本次密码后才返回校验状态。刷新只接受控制面曾为该网关签发的凭据引用，不提供按租户枚举或任意用户名批量读取。控制面明确返回网关停用或令牌无效时，中继立即停止使用缓存并拒绝新连接。

## 备选方案

| 方案 | 网关整包、身份与部署 | 取舍 |
| --- | --- | --- |
| GOST 直连控制面，仅在控制面缓存 | 原版 GOST 继续持有逐网关 `auth` 令牌，采集器持有 `report` 令牌，无本机中继。 | 可减少查库。控制面或链路中断时，新连接全部被拒。 |
| 网关本机认证中继 | 沿用原版 GOST，把中继放进现有网关 Go 进程。GOST 使用本机令牌，Go 进程分别持有远端 `auth` 和 `report` 令牌。 | 支持短时离线准入，增加认证状态同步、凭据保护和恢复追平逻辑。 |
| GOST 本地 `auths` 或文件热加载 | 原版 GOST 可直接加载本地用户名密码。跨机分发和刷新需要独立的受认证同步机制，采集仍使用 `report` 令牌。 | 本地认证成功返回用户名作为 ID，无法一起检查凭据有效期、来源和额度。`plugin` 配置优先于同一认证器的本地配置。另挂本地认证器时，多个认证器按首个成功放行，控制面的明确拒绝也会进入兜底。 [配置解析](https://github.com/go-gost/x/blob/v0.28.1/config/parsing/auth/parse.go) · [本地与组合认证](https://github.com/go-gost/x/blob/v0.28.1/auth/auth.go) |

## 取代条款

- [ADR 0001](0001-usage-data-model.md) 的「额度」「充值、调整与准入」由本 ADR 补充网关缓存与准入时效，并以欠费估算取代「允许有界欠费」及「超卖上限」的表述。
- [ADR 0002](0002-service-and-proxy-identity.md) 的「网关服务身份」「代理凭据」由本 ADR 取代 GOST 持有远端 `auth` 令牌、凭据停用对所有网关立即生效的约定。
- [ADR 0003](0003-reporting-and-usage-contracts.md) 的「`gateway_auth.proto`：认证与准入」由本 ADR 取代该认证入口的部署位置与额度读取路径。GOST 的 HTTP 请求与响应形态沿用原契约。

## 影响与验收

- #3 验证暖缓存短时离线通过，冷缓存、过期和网关 Go 进程重启时拒绝。覆盖凭据到期、停用同步、来源拒绝、稳定 `clientID`、令牌隔离及认证器注册检查。
- #5 在原版 GOST 与同机采集器整包中验证认证中继和跨机分权。恢复判定复用 #4 的批次提交确认，#4 的入库接口和事务边界沿用 ADR 0003 和 ADR 0004。
- #10 在目标环境以每秒 2 万以上新连接和 3 秒内集中重试为测试输入，记录暖缓存、冷缓存和恢复阶段的成功率与延迟。网关容量以实测通过负载为准。
- #14 验证上报单独故障时额度不续期，补齐本机截点后按扣减后的额度恢复准入。验收覆盖失效窗口、额度门槛、已有连接继续计量和按记录时间幂等补报。
