# #10 跨机器双租户端到端验收准备

基线为 `origin/main` 的 `05aee71`，包含 #14 的合并提交 `2746523`。#6、#7、#8 和 #14 已关闭。#14 已交付充值抵欠、网关额度拦截和恢复追平逻辑。分机验收于 2026-11-13 完成。集中关闭和重连压测由 [#11](https://github.com/DuanJinTaoToday/proxy/issues/11) 单独验收。

## 悟空联调策略

### 小流量实测

在当前 Windows 工作机上分别经 `154.81.157.72:12347` 和 `154.81.157.73:12347` 使用 `socks5h` 访问 `api.ipify.org` 和 `checkip.amazonaws.com`。每次请求新建连接，共 19 次，11 次 HTTP 200，7 次在 TCP 建立前超时，1 次在 TCP 已建立后超时。测试连接超时设为 4 秒，总超时设为 9 秒。

| 场景 | 观察结果 |
| --- | --- |
| 同 SID、同入口重连，`sidtime=3600` | 首轮 `.72` 三次成功返回 `182.11.182.183`，首末请求启动时间相差 58 秒。期间一次回切 `.72` 的请求在 TCP 建立前超时。 |
| 同 SID 跨入口 | 首轮 `.73` 两次成功均返回 `178.134.131.53`，与 `.72` 不同。换目标后的三次跨入口对照请求均超时。 |
| 不同 SID | 首轮另一个 `sidtime=3600` SID 在两个入口各尝试一次，均在 TCP 建立前超时。样本未覆盖不同 SID、同参数的出口对照。 |
| 短有效期参数 | `sidtime=10` 在 `.72` 的两次成功返回相同出口，启动时间相隔 27 秒，中间两次 TCP 超时。`sidtime=1` 在 `.72` 的四次成功返回同一出口，首末启动时间相隔 28 秒。 |

本轮已观察到切换入口可能更换出口。`sidtime` 的单位、取值范围、计时起点、访问是否续期及到期行为仍需供应商确认。短参数请求成功且出口相同，无法据此判定会话是否过期，或推断 `3600` 的实际有效期。


### SID 分配

- 在同一悟空供应商账号下，每个租户分配一个独立的九位数字 SID，使用 `100000000`–`999999999`。持久保存账号、租户和 SID 的映射，在账号内校验唯一性，冲突时重新分配。联调先为 A、B 和探测预留不同 SID。
- 客户端重连、网关重启和入口切换时沿用租户 SID。上游继续发送 `sidtime=3600`。应用不依据该参数定时轮换 SID，出口可能随入口或重连变化。
- 分机联调在一台网关上使用 `wukong-pool.example.yaml`，A、B 可共用监听地址。SID 以供应商账号为命名空间，保存在网关持久 spool。同一供应商账号的多个独立网关需要共享分配状态，本轮使用单网关。

### 入口池

- 从网关宿主机用独立探测 SID 检查配置的各个入口。探测完成 SOCKS5 认证、CONNECT 和已知 HTTPS 目标的响应校验，分别记录 TCP、SOCKS5 和 HTTPS 阶段。初始状态为待验证，连续 2 次成功后进入可用池。
- 联调初值为每 5 秒一次探测，每次 HTTPS 检查总超时 2 秒。可用入口连续 3 次可归因于入口的失败后摘除，连续 2 次成功后恢复。成功清零失败计数，失败清零成功计数。HTTPS 目标错误用备用目标或独立直连结果复核。归因未明时告警，不将该次结果计为入口故障。
- 新连接优先使用本租户上次成功的健康入口。该入口不可用时按配置顺序选取健康入口，继续使用租户原 SID。入口摘除和恢复只影响新连接，恢复后不主动切回仍在健康入口上的租户。全池无可用入口时拒绝新连接并告警，探测继续运行。
- 在目标网关宿主机复测并校准探测超时。以本轮采用的公网查 IP 目标作参考，其正常请求也可能超过 2 秒。联调应选有稳定响应且可控的探测目标，再用受控入口故障验证摘除、恢复和既有连接行为。主探测发生 CONNECT 或 HTTPS 错误时，用独立备用目标经入口及直连复核，各检查最多 2 秒。


## 分机验收结果

2026-11-13，本机运行控制面 HTTPS 集成实例及 PostgreSQL 17，Ubuntu devbox 运行 Linux amd64 网关、原版 GOST v3.3.3 和本地 Recorder。控制面和客户端端口经 SSH 转发，测试实例仅监听回环地址。使用悟空 .72 和 .73 两个真实入口，探测主目标为 gstatic 的 204 地址，备用为 ipify。联调实测 HTTPS 请求约 2.4–8.8 秒，探测超时设置为 12 秒，默认仍为 2 秒。

| 验收 | 结果 |
| --- | --- |
| 双租户与对账 | 两租户使用各自凭据经真实悟空请求，租户日用量与按网关和时间查询的运营用量分别对上 1,607 和 5,663 字节。跨租户及越权运营请求返回 403。A 连接关闭前已查询到 1,607 字节。 |
| 额度和欠费 | 用运营调整将 A 可用额度归零，控制流量规模。新连接认证拒绝，旧连接继续转发并形成 4,369 字节欠费。充值先抵欠并恢复新连接。 |
| 停机、丢响应和补报 | 控制面测试 HTTP 入口整体返回 503 时，既有连接仍传输，已确认用量和水位不变。恢复后在 PostgreSQL 提交成功时断开 HTTPS 响应，网关重报并从 11,543 追到 13,913，新增 447 字节只计一次。 |
| GOST 异常退出 | 在 A 的另一条长连接已有 interim 时强制终止联调 GOST 子进程，重启网关并复用 spool。运营查询只返回一条有租户和会话归属的可能缺口，旧代次为 `5EDN6MFDMZ7SZZGS4XTHJ5FBNZ`。 |
| 上海跨日 | 使用专用上报样本验证午夜两侧分别入两天，每天 18 字节。 |
| 入口池故障 | 原版 GOST 配两个受控入口验证摘除、恢复、既有连接和全池不可用拒绝。分机使用真实入口验证健康探测和双租户转发，受控摘除测试在本地完成。 |

复跑 `TestWukongCrossHostDualTenant` 需要隔离的 PostgreSQL DSN、悟空测试凭据，以及 devbox 上新建的 `/tmp/proxy-issue10.*` 目录。将 Linux amd64 网关和原版 GOST v3.3.3 分别放入该目录，文件名为 `gateway` 和 `gost`。本机注入 `PROXY_CONTROL_TEST_DSN`、`PROXY_CROSS_HOST_DIR`、`WUKONG_USERNAME` 和 `WUKONG_PASSWORD` 后运行 `go test ./apps/proxy-control/integration -run '^TestWukongCrossHostDualTenant$' -v -count=1`。复跑使用新目录，避免复用上一轮 Recorder 水位。


## 环境准备

1. 在两台联调宿主机上分别运行控制面和网关，记录构建 SHA、操作系统、时区和时钟同步状态。控制面使用 PostgreSQL 并执行 Goose 迁移。网关使用 GOST v3.3.3，Recorder 仅落网关本地盘。核对网关可访问控制面 HTTPS，私有 CA 通过 `data.acl.control.ca_file` 配置。
2. 预置独立的网关 `auth` 和 `report` 令牌，以及 GOST 到本机认证中继的令牌。准备 A、B 两个租户、各自管理员与普通成员、只读运营和计费运营账号。给 A、B 发放独立的 SOCKS5 凭据，准备充值外部单号。访问地址和凭据通过联调环境注入。
3. 准备可精确核对字节、保持长连接和控制请求时序的 SOCKS5 目标，以及从网关宿主机可访问的悟空测试入口。准备只作用于联调实例的 HTTP 故障注入入口，可单独阻断上报，或在控制面提交成功后丢弃响应。

## 本地回归

使用原版 GOST v3.3.3、两个本地可控 SOCKS5 入口和 HTTPS 目标验证 A、B 的九位 SID 隔离、同租户不同凭据共用 SID、重开状态后保留 SID、故障后新连接切换及原连接继续传输、恢复后不主动切回，以及全池不可用时拒绝可直连目标。分机环境需填写实际入口和探测目标，并保留网关探测日志与 Recorder 对账证据。

## 执行与记录

| 场景 | 执行步骤 | 通过证据 |
| --- | --- | --- |
| 受控双租户与权限 | A、B 各自建立连接并发送不同字节样本。保持 A 的连接，等到出现 `interim`。两边互查对方用量与余额，并分别尝试访问运营接口。 | A 在关闭前已能查询用量，B 只看到自己的流量。越权返回 403。运营按租户、网关、时间段查询，与对应 Recorder 和租户日用量核对。 |
| 额度与欠费 | 设置 A 上行 1.2 倍、下行 1 倍，充值 100 MiB，门槛 10 MiB。通过已有连接消耗额度，等待网关同步后分别尝试 A、B 新建连接。继续通过 A 的旧连接发送数据。充值 A 并重放同一单号。 | A 新连接在门槛以下被拒，B 新连接成功。A 旧连接继续计量形成欠费，充值先抵欠、只入账一次，达到门槛并同步后恢复准入。留存余额、流水、授予和用量对账。 |
| 控制面停机与上报单独中断 | 先预热两个租户的认证状态。分别停止控制面、仅阻断上报端点，保持长连接生成 Recorder 记录。记录旧快照的最后有效同步时间。恢复后记录各文件恢复截点和连续确认水位。 | 旧快照最多用 30 秒。上报恢复后所有文件达到各自截点，才使用已扣减的余额重新续期。低于门槛继续拒绝。 |
| 提交成功后丢响应 | 让控制面成功提交一个批次，丢弃返回网关的 HTTP 响应。恢复响应并等待网关重发。 | 首次提交后数据库确认水位已前进，网关本地水位仍旧。重发后两边水位一致，汇总和额度仅扣一次。 |
| GOST 异常退出 | 建立一条已正常结束的连接和一条已有 `interim` 的长连接，强制终止联调 GOST。重启网关并等待旧代次补报、核对。 | 完整记录只计一次。缺少 `final` 的会话提示可能缺口，正常结束会话无缺口。记录旧 `boot_id`、确认偏移和缺口类型。 |
| 上海自然日跨日 | 让受控长连接在上海午夜两侧各产生采样，或者通过联调上报接口提交有已知时间和字节数的专用样本。 | 两天分别归集，租户日用量、运营分桶和 Recorder 增量一致。记录采用实时时间或样本时间。 |
| 真实悟空双租户 | 配置池模板、候选入口和两个受控 HTTPS 目标。先确认两次健康探测通过，再从联调客户端使用 A、B 各自凭据访问已知 HTTPS 目标。在联调网关侧控制候选入口可达性，逐个复测摘除、恢复及全池拒绝。 | 两个租户均完成转发与用量归集。记录 SID 分配结果、入口探测、摘除和恢复时刻、目标响应、运营对账，以及切换对既有连接的观察。 |
