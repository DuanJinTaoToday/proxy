# Issue #11 devbox 容量基线

基线代码为 `4be59a1`。devbox 运行 Linux amd64（内核 `5.15.0-113-generic`），有 2 vCPU、1,931 MiB 内存、无 swap，测试前 ext4 根盘约有 31 GiB 可用空间。测试进程和其子进程的 `nofile` 软限为 8,192。

在同一宿主机上运行压测客户端、网关侧原版 GOST v3.3.3、受控 SOCKS5 上游和 TCP echo 目标，均走回环地址。网关侧使用项目的 GOST 启动封装、文件 Recorder 和 HTTP 认证中继。认证中继使用集成测试的控制面替身，本轮未运行用量采集上报或控制面入库。每轮启动独立网关实例，使用临时 Recorder 目录，采样周期为 1 秒。

## 参数与判定

- 候选档位为 100、250、500、1,000 条已建立会话。每档连续三轮达标才计为通过，首轮不达标时停止升档。
- 触发后关闭所有候选会话，在 3 秒内按每 5 ms 一次的计划发起 600 次 SOCKS5 CONNECT，每次超时 2 秒。发起不足或单次发起偏离计划超过 50 ms 时判为无效轮次。延迟从发起建连计到收到 CONNECT 成功响应。
- 新连接成功率至少 99.5%，成功探测 P99 不超过 250 ms，失败和超时均计入成功率分母。
- 触发后 5 秒内读齐候选会话的 `final`。按客户端地址核对候选集合，要求有效记录、唯一 `sessionID`、无缺失或重复，文件无坏行。探测连接的 `final` 不纳入候选集合。
- 可用内存低于 256 MiB 时取消测试。在独占窗口观察其他服务，发现受影响时中止。

## 复跑

在仓库根目录构建测试二进制。将它和 `apps/proxy-gateway/gost/auth.example.yaml` 放在 devbox 的隔离目录中，分别置于 `integration/capacity.test` 和 `gost/auth.example.yaml`。

```powershell
$env:GOOS = 'linux'
$env:GOARCH = 'amd64'
go test -c ./apps/proxy-gateway/integration -o capacity.test
```

在 devbox 的 `integration` 目录执行以下命令。GOST 路径须指向原版 v3.3.3。

```sh
ulimit -Sn 8192
PROXY_RUN_CAPACITY=1 PROXY_GOST_TEST_BINARY=/path/to/gost \
  ./capacity.test -test.run '^TestGOSTConcentratedCloseCapacity$' -test.v -test.timeout 4m
```

## 实测结果

devbox 基线最高通过档为 **500 条会话**。1,000 条档首轮 P99 为 **462.01 ms**，超过 250 ms，按计划停止。该轮 600 次新连接均成功，1,000 条候选 `final` 均在 568.36 ms 内读齐。1,000 条档未跑第二、三轮。

候选会话和探测分别绑定 `127.0.0.1` 和 `127.0.0.2`，避免探测复用刚关闭的候选源端口导致误计。正式统计仅使用修正后的完整运行。压测端、上游和网关共享 2 vCPU，结果包含同机资源竞争。

另从 devbox 通过真实悟空 SOCKS5 入口发起一次 HTTPS 冒烟，返回 HTTP 204，用时 2.71 秒。#11 以本次 devbox 基线结论关闭。正式目标环境确定后，再按相同口径复测。
