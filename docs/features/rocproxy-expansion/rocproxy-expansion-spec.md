# RocProxy 官网与售后扩展 Spec

**状态：已发布** · [GitHub 扩展 Spec #100](https://github.com/DuanJinTaoToday/proxy/issues/100) · 2026-11-25

本 Spec 补充 [首版商业交付 Spec #36](../proxy-first-release/proxy-first-release-spec.md)。生效后，客户注册、登录、找回密码和运营租户搜索采用本文的邮箱规则。已有的商品开售、钱包支付、动态代理和静态购买及续费行为以 #36 为基线。本次扩展的场景走查和拆票评审使用本文的业务规则。 [需求讨论与共享设计](../../product/rocproxy-expansion-analysis.md)

## 问题陈述

游客需要在登录前查到实际在售的规格和价格，并能在购买遇到问题时找到人工客服。现有客户开户和找回密码依赖手机号或运营处理。静态 IP 客户遇到线路故障时，缺少自助换号入口。推广员也缺少从邀请注册到首购、复购、佣金和钱包转入的完整记录。官网与控制台需要使用已经选定的 RocProxy 品牌素材。

## 解决方案

| 需求 | 交付承诺 |
| --- | --- |
| 首页内容与风格 | 首页对应动态住宅 GB 和静态住宅 IP，采用**云网钴蓝基建风**（参考 Cloudflare/阿里云克制专业质感与辣椒 HTTP 商业转化留白节奏），提供产品起售价与购买入口、覆盖地区、专业解决方案、常见问题和客服入口。本批仅重构官网首页与公开报价页，登录注册页、租户控制台与运营控制台后续统一改版；接入教程归入后续帮助中心。首页起售价与 10 国覆盖地区先作静态展示，开售前按实际目录调整。 |
| 皇冠静态 IP | 本批交付单条独享静态 IP 的同地区免费换号、租户固定额度、运营查记录和调额。后续能力见皇冠接入计划。 |
| 分销 | 一级直推。按合格订单结算顺序区分首购和复购，按全站可配置的两档费率长期返佣。推广员可把可用佣金转入自己的站内钱包。 |
| RocProxy Logo | 全站采用**钴蓝版**提案 A「鹏翼路由」（`#3b82f6` → `#1e3a8a`，点缀 `#38bdf8`）及 RocProxy 字标，用于官网、客户控制台和运营台的品牌入口，以及浏览器标题和图标。 |
| 邮箱认证 | 邮箱加密码登录，注册前验证邮箱，提供邮件找回密码与运营协助恢复。客户手机号注册和登录入口移除。 |
| 联系方式 | SaleSmartly Free 提供站内人工客服。Telegram 和 QQ 点击跳转，联系电话点击复制并反馈结果。首页先行交付视觉与交互入口，真实工作台联验由 `#102` / `#112` 承接。 |
| 游客套餐价格 | 游客可在公开报价页（采用新版钴蓝视觉）查询全部在售动态套餐及静态规格和价格；静态报价支持通过购物车跳转控制台购买（未登录跳转登录页）。前端对客展示中停售与无库存可统一呈现，查询失败单独提示重试；登录后保留选择并按当前价格和库存重新确认。 |

## 用户故事

### 官网、品牌、联系方式与游客价格

1. 作为游客，我希望看到动态住宅 GB 与静态住宅 IP 的区别和适用场景，以便选择产品。
2. 作为游客，我希望在首页找到产品介绍、起售价与购买入口、覆盖地区和解决方案，以便自行了解下单条件。
3. 作为游客，我希望看到在售动态套餐的档位、容量和价格，以便比较成本。
4. 作为游客，我希望按地区和租期查看静态 IP 的类型、可购量和报价，并通过购物车进入购买，以便确定采购规格。
5. 作为游客，我希望能区分暂无可购（停售或无库存）和查询失败，以便决定等待、换规格或重试。
6. 作为游客，我希望登录或验证邮箱注册后回到原购买流程并保留已选规格与数量，以便继续购买。
7. 作为客户，我希望价格或库存变化时看到最新报价和可购量，以便确认新的购买条件。
8. 作为游客、客户或运营人员，我希望在官网、控制台和浏览器标签页看到确认的 RocProxy 品牌标识，以便识别服务入口。
9. 作为游客或已登录客户，我希望通过站内聊天联系人工客服，以便处理购买和售后问题。
10. 作为客户，我希望客服先核实订单归属再处理订单，以便保护我的订单信息。
11. 作为游客或客户，我希望点击 Telegram 或 QQ 打开正式客服渠道，以便使用常用的联系方式。
12. 作为游客或客户，我希望点击电话号码即可复制并得到反馈，以便拨打或保存号码。

### 邮箱开户和账户恢复

13. 作为新客户，我希望用一次性邮件验证码验证邮箱并注册，以便使用自己的邮箱管理账号。
14. 作为新客户，我希望验证码过期或邀请码无效时能修正后继续，以便完成注册。
15. 作为新客户，我希望在注册完成时同时获得唯一的租户管理员、钱包和流量账户，以便登录后直接使用。
16. 作为客户，我希望使用注册邮箱和密码登录，以便进入已有租户。
17. 作为忘记密码的客户，我希望通过邮件中的一次性链接重置密码，以便自行恢复访问。
18. 作为客户，我希望重置密码后旧会话失效，以便撤销旧设备上的访问。
19. 作为失去原邮箱访问权或需要更换邮箱的客户，我希望运营核验归属并让我验证新邮箱，以便继续使用原租户和账户资产。
20. 作为运营人员，我希望用注册邮箱或主账号名查找租户，以便协助找回和核实交易。

### 一级直推和佣金

21. 作为已验证邮箱的客户，我希望直接获取自己的邀请链接和邀请码，以便推广 RocProxy。
22. 作为受邀新客户，我希望邀请链接在当次注册带入邀请码，也可以手填有效的邀请码，以便确认直接推荐人。
23. 作为新客户，我希望可以跳过邀请码，或在邀请码无效时更正或清除，以便自行开户。
24. 作为直接推荐人，我希望推荐关系在对方成功注册时固定，以便后续订单可以归属到同一个推广员。
25. 作为直接推荐人，我希望被推荐客户最先完成结算的正净扣款订单按首购费率计佣，以便收到首购佣金。
26. 作为直接推荐人，我希望被推荐客户后续完成结算的正净扣款订单持续按复购费率计佣，以便获得长期佣金。
27. 作为直接推荐人，我希望实际以钱包支付的动态套餐、静态 IP 购买和保号续费均参与返佣，以便不同商品按同一口径计佣。
28. 作为推广员，我希望看到邀请来源、被推荐客户的匿名标识，以及合格订单的商品、结算时间、净扣款、佣金金额和状态，以便独立核对。
29. 作为推广员，我希望在站内填入金额并把可用佣金转入自己的钱包，以便购买商品。
30. 作为推广员，我希望转入请求超时后可以用同一请求重试，以便查看原结果且只发生一笔转入。
31. 作为运营人员，我希望配置全站统一的首购和复购费率，并按实际费率和规则核对历史记录，以便管理推广成本。
32. 作为运营人员，我希望暂停和恢复异常推广资格，以便控制新绑定和新计佣，并保留已结算记录。
33. 作为推广员，我希望暂停推广期间仍可转入已入账的佣金，以便使用已有余额。

### 皇冠静态 IP 与售后

34. 作为租户管理员，我希望能对已交付且有效的一条独享静态 IP 发起同地区免费换号，以便自助恢复使用。
35. 作为租户管理员，我希望看到租户剩余换号次数，以便在旗下订单和 IP 之间安排额度。
36. 作为租户管理员，我希望提交前知道旧 IP 将失效，以便准备更新本地接入配置。
37. 作为租户管理员，我希望超时后仍能查询原换号记录，以便确认结果并避免重复扣减。
38. 作为租户管理员，我希望换号确认后能复制和导出最新接入参数，并继续对同一分配续费，以便恢复业务。
39. 作为租户管理员，我希望看到新 IP 的生效状态，并在拨测持续失败时找到人工客服，以便获得帮助。
40. 作为授权运营人员，我希望按租户查询换号历史、结果和额度变化，以便处理异常并对账。
41. 作为授权运营人员，我希望手动增加或减少租户额度，并能查到调整历史，以便处理额外换号需求。
42. 作为授权运营人员，我希望处理长时间待核实的换号，并依据供应商证据结案，以便解除已确认结果的额度占用和操作冲突。
43. 作为客户，我希望在部分交付的订单中更换已经交付的独享 IP，同时等待剩余明细处理，以便继续使用已有资源。

## 实现决策

### 皇冠静态 IP

- 每个租户初始有 **10 次**固定换号额度，由该租户所有订单和静态 IP 共用。每实际成功更换一条 IP 扣 1 次。购买、续费和时间经过均不会补充额度。额度用尽时拒绝新换号并保留查询入口。计费运营可手动增减额度，系统记录操作人、时间、变动次数和前后额度。皇冠为 RocProxy 的 Partner ID 补充供应商额度，平台自助规则以租户额度为准。
- 首批一笔请求更换一条已交付且有效的独享静态 IP，由平台在皇冠同一可售地区分配替代 IP。调换免费，钱包和订单结算金额均无变动。部分交付的采购单中，已交付且有效的分配可以换号，未交付的部分继续按原采购规则核单和结算。共享静态 IP 的换号在皇冠联调通过后另行开放。
- 首版上线前，为既有静态 IP 分配补齐独立、稳定的平台分配 ID，新分配创建时生成该 ID。控制面 `v1`、控制台及验收用例同步切换。列表、接入配置、导出、续费和换号等对客操作统一使用平台分配 ID，服务端拒绝以旧供应商明细 ID 作为分配标识提交的请求。皇冠订单明细 ID 继续用于供应商交付、核对及续费。换号更新同一分配的连接信息，后续请求使用原平台分配 ID。
- 提交校验租户归属、产品类型、有效期、许可地区、操作冲突和租户剩余额度，在同一事务记录请求并预占 1 次。运营调额须覆盖已有预占。同一请求标识重试返回原记录。换号、续费在提交时互相检查并拒绝同一分配未终结的冲突操作，后续改密和释放沿用同一边界。事务沿用订单与静态分配的既有锁定顺序，皇冠网络调用在本地事务外执行。 [事务边界](../proxy-first-release/proxy-first-release-data-model.md#事务与并发)
- 原采购核单按原采购明细与分配归属识别已交付项。有换号历史时，通过当前分配及换号记录对照原交付。旧采购快照只用于核实原明细和剩余交付，当前连接参数由已确认的最新换号维护。核单可以继续新增剩余交付或退回未交付款项，已交付数量和本次换号次数均只记一次。
- 系统自动核对。回执超时或信息不足时，系统保留预占，用皇冠调换记录和原订单详情只读核对。查单超时或缺少唯一匹配时，系统继续待核实。自进入待核实起 **15 分钟**仍无法确认结果时，转入运营异常队列并继续自动核对。客户可在原记录查询并联系人工客服。
- 运营人工结案。入队后，授权运营可为原请求提交核查证据。确认实际换号成功时，更新参数并计 1 次。确认上游未执行时，释放预占并解除该操作造成的互斥。可用的未执行证据包括皇冠明确核查确认，或本地持久记录证明请求从未发出并已取消发送。仅查无记录或原 IP 未变时，继续保持待核实。
- 迟到结果。自动核对与人工处理同一记录时，只有一次结案可以提交。结案后收到相同结果只留证。矛盾结果由运营核实实际调换和当前分配，按实际成功次数作一次有审计的额度及状态更正。较早结果不能覆盖较新的已确认配置。
- 皇冠确认成功后，在同一事务更新原分配，使用返回的 `proxyid`、`ip`、`port`、`p_user`、`p_pass` 和 `stoptime`，并将 1 次预占转为已用。通过查单恢复时采用当前分配对应字段，`proxy_id` 对应 `proxyid`。确认后复制和导出立即使用新参数，续费仍提交原皇冠明细 ID。连续操作以同一分配的已确认状态为准。
- 平台异步拨测任务经可访问皇冠代理的网络出口使用新参数拨测。拨测期间显示「生效中」，客户可复制或导出已经确认的新配置，也可在换号确认后续费。拨测成功显示「可使用」。达到拨测重试预算后仍无成功结果时，保留已确认的换号及其额度记录，引导客户联系人工客服。同一操作的重试始终返回原记录，拨测结束后客户可按租户额度发起新的换号。执行部署、超时和重试策略在实现切片确认，并用真实 SOCKS5 验证。 [换号联调](../../integrations/ipcrown-static-ip.md#同地区换号隔离实测)

### 邮箱认证与邀请归属

- 控制面负责账号、密码和会话，邮件服务负责投递。注册、登录、找回、邮箱恢复和运营按邮箱搜索统一使用去除首尾空白、全小写的邮箱键，保留 `+` 子地址和点号。校验邮箱格式和字节长度，最长 254 字节。向用户实际验证的地址投递。
- 注册验证码、找回链接和邮箱恢复凭证按用途和目标邮箱绑定，具有有效期及一次性使用约束。发送注册验证码和请求找回均采用统一公开回执，发信按规范化邮箱及请求来源实施频控。单份注册验证码连续验证失败 **5 次**即失效，可在频控范围内重新申请。有效验证码通过、邀请码校验失败时，保留该验证码供修正后提交。
- 注册密码至少 12 位。最终提交在同一事务验证并消费验证码、复核邀请码、保存唯一直接推荐人或无推荐人的状态，并创建租户、唯一管理员、零余额钱包和流量账户。规范化后相同的邮箱并发注册只成功一次。
- 邀请码选填，有效的手填邀请码优先于邀请链接带入的值。链接值保留在当次注册流程，后续可重新打开原链接或手填。邀请码无效或推广资格已暂停时，客户可更正或清除后继续。系统拒绝重复开户、同租户自邀和成环归属。跨邮箱的同主体套利由运营核查。注册后邀请归属固定。已验证邮箱的客户可直接参加推广。
- 自助找回在验证原邮箱的一次性链接后设置新密码，同时消费凭证并撤销旧会话。运营协助恢复时，先核验租户归属并预检目标新邮箱。邮箱已被占用时拒绝发信。新恢复申请成功创建时，同一租户此前未消费的恢复链接立即失效，随后向本次目标邮箱发信。客户凭新链接验证邮箱并设置新密码，使用时无需登录旧账号。完成事务复查该凭证仍有效及邮箱唯一性，一并更新邮箱和密码、消费凭证、撤销旧会话及记审计。若目标邮箱在完成前被占用，拒绝换绑并保留原账号。恢复沿用原租户 ID、余额、订单和邀请归属。
- 保留现有授权运营重置密码作为核验归属后的兜底操作，记录操作者并撤销旧会话。该入口只更新密码，邮箱变更通过上文的新邮箱验证流程。
- 项目处于首版上线前，现有调用方随本次交付同步更新。客户注册登录直接在 `v1` 切换为邮箱。在 Protobuf 中移除 `phone`，用 `reserved` 保留原字段编号和名称。控制面、控制台、种子数据、运营租户搜索和验收用例一次性切换，服务端拒绝旧手机号载荷。运营登录及代理子账号沿用各自的权限边界。首版发布后的不兼容变更遵循 API 版本规范。 [邮箱认证共享设计](../../product/rocproxy-expansion-analysis.md#邮箱认证共享设计已确认) · [接口版本约定](../../standards/proxy-development-conventions.md#接口与依赖)

### 分销结算与佣金转入

- 合格订单须已完成结算，且商品订单的钱包净扣款大于零。钱包实际消费统一计入，包括由佣金转入的钱包余额。动态套餐购买、静态 IP 购买和保号续费均适用。部分交付按最终净扣款计算。
- 订单终态结算事务记录完成时间，并按同一购买租户的结算顺序判定首购和复购。每个被推荐租户最多有一个首购，同一订单重放只记一笔。零净扣款订单无佣金且不占首购资格。正净扣款订单产生 0 分佣金时仍记首购或复购及实际结果。
- 佣金只给购买租户的直接推荐人。全站统一首购和复购两档，费率可设为 **0% 至 100%**，最小调节单位 **0.01 个百分点**。按订单完成结算时的费率计算，每笔四舍五入到人民币分，并保存实际费率、推荐归属和规则版本。
- 订单结算与记佣在同一事务提交。结算只涉及购买者钱包和直接推荐人的佣金账户。转入事务涉及该推广员自己的钱包和佣金账户。涉及两类账户时遵守统一的锁定顺序，保留既有订单和钱包边界。实现切片验证跨租户并发结算、转入重试和单笔首购唯一。
- 暂停推广时停止新邀请绑定和新计佣。期间完成结算的合格订单仍判定首购或复购，佣金记 0 分。已入账的可用佣金仍可转入，恢复推广后从后续结算继续计佣。
- 推广员在可用余额内填写正数金额并申请转入自己的站内钱包。扣佣金、增加钱包余额和记录转入流水由同一事务完成。同一请求重试返回原流水。转入使用独立的佣金转入流水类型，客户和运营均可区分和筛选，累计充值继续只统计人工充值。推广员可按匿名客户标识查看其相关订单和佣金。 [分销共享设计](../../product/rocproxy-expansion-analysis.md#分销共享设计已确认)

### 公开报价、品牌与客服

- 游客可在公开报价页（`/:locale/pricing`，采用新版云网钴蓝视觉）完整查价，复用现有商品和静态报价 API。动态套餐展示全部在售档位，静态报价覆盖全部已开售的独享和共享规格，并提供购物车选配后跳转控制台购买（未登录时先跳转登录页）。前端对客展示可将「停售」与「无库存」等同呈现为暂不可购，但查询失败须单独展示并可重试；服务端与运营台的动态/静态独立开售开关及购买拦截维持不变。首页先采用固定起售价与 10 国静态覆盖地区展示，开售前由产品方按实际目录调整；接入教程归入后续帮助中心。
- 购买意向保留规格、地区、类型、租期和数量（含静态购物车选配项），适用于登录及邮箱验证注册后的站内回跳。返回购买流程后按当前价格、库存和开售状态复核。需要重新确认时，订单及钱包保持原状，待客户确认后再提交。
- 公开静态查询复用短期报价快照并合并同规格正在进行的查询，公开流量使用独立的上游请求预算，给下单和续费复核预留容量。公开查询受限或快照无法刷新时返回明确的暂不可查询状态。成交仍走实时复核。缓存新鲜度、限流和供应商预算参数由实现切片确定并验收。
- 官网、客户控制台和运营台全站切换为**钴蓝版**提案 A（`#3b82f6` → `#1e3a8a`，点缀 `#38bdf8`）、RocProxy 字标和产品标题，浏览器图标使用同一品牌素材。本批仅重构官网首页与公开报价页的云网钴蓝视觉，登录注册页、客户控制台与运营控制台主题后续统一改版。
- SaleSmartly Free 在独立来源运行，官网和客户控制台以跨源 `iframe` 提供访客模式站内聊天。客服脚本的来源与控制台会话、父页面和订单数据隔离。部署的内容安全策略只允许嵌入指定客服来源，并限制客服页面可被哪些 RocProxy 来源嵌入。嵌入只传递聊天所需的非敏感信息。联验确认 Free 插件能加载、保持访客会话并收到人工回复。若嵌入无法通过验收，独立客服页方案需先评审站内客服体验。客服核实订单归属后处理订单。Telegram 和 QQ 使用正式客服链接，电话号码点击复制并反馈结果。首页先交付客服视觉与交互入口，真实联验由 `#102` / `#112` 承接。 [客服接入讨论](../../product/rocproxy-expansion-analysis.md#官网与游客价格)

## 测试决策

优先从现有公开、租户和运营控制面接口观察业务结果。通过同一入口读取订单、额度、钱包、佣金和分配，覆盖主路径、并发、重复提交及回执超时。复用已有的商品、钱包、开户、静态购买和续费验收方式。真实邮件投递、人工聊天、Logo 和页面回跳使用浏览器验收，皇冠换号及数据面生效通过隔离上游及 SOCKS5 实拨验证。 [采购及续费验收基线](../proxy-first-release/issue-52-static-release-acceptance.md) · [换号联调证据](../../integrations/ipcrown-static-ip.md#同地区换号隔离实测)

| 场景 | 操作与预期 |
| --- | --- |
| 首页、品牌与客服 | 核对云网钴蓝代表页的产品内容、静态起售价入口、10 国覆盖地区、解决方案、FAQ 和购买入口，官网、客户控制台、运营台的钴蓝提案 A 图标、RocProxy 字标及浏览器标题一致。首页先交付客服入口展示位，真实访客会话保持、隔离边界、人工回复、正式跳转和电话复制由 `#102`/`#112` 联验。 |
| 游客报价到购买 | 在未登录时通过新版钴蓝公开报价页查询全部在售动态档位及独享、共享静态报价（前端停售与无库存可统一呈现，查询失败单独可重试）。静态报价支持通过购物车跳转控制台（未登录跳转登录页），分别通过登录和邮箱验证注册保留购买选项。服务端复核价格和库存，待重新确认期间订单和钱包无变动。模拟公开查价高峰，核对查询重用及上游限额，已登录客户仍可复核购买和续费。 |
| 邮箱开户与邀请 | 走真实发信，验证已注册和未注册邮箱的统一回执、错误次数达到上限及过期重放。验证规范化邮箱唯一、邀请码优先级和清除后继续、并发注册、旧手机号载荷拒绝，核对唯一租户管理员、余额和固定归属。 |
| 登录与账户恢复 | 验证找回链接一次性使用。运营授权恢复时，客户从目标新邮箱打开链接，验证成功并设置新密码后旧密码和旧会话均失效。验证目标邮箱发信前已被占用时拒绝发信，发信后发生并发占用时拒绝换绑并保留原账号。为同一租户重新发起恢复后，旧恢复链接不能使用。既有运营重置入口独立验权。恢复后继续访问原钱包、订单和邀请归属。 |
| 换号交付、部分订单与续费 | 让部分交付采购单中的有效独享 IP 换号，核对少 1 次、钱包无变动，旧采购快照不覆盖新配置且剩余采购继续结算。验证既有分配补齐平台 ID，对客入口统一使用该 ID，换号前后平台 ID 一致。生效期间复制和导出采用新参数，可用原皇冠明细保号续费。拨测结束后按额度允许新换号。使用 SOCKS5 核对实际连通性。到期、未交付、共享及跨地区申请在首批拒绝。 |
| 换号额度与未知结果 | 同租户只剩 1 次时让两笔订单同时提交，只有一笔预占成立。验证调额审计、换号与续费双向互斥、同请求重试。已执行但回执超时仅核销 1 次。模拟查单超时和查无记录，系统仍保留预占。满 15 分钟转运营，凭已执行或未执行的证据分别计次或释放，并解除该操作造成的互斥。验证自动和人工并发结案只有一次生效。核对迟到重复结果、冲突证据和旧结果均按记录处理，较早结果不会覆盖新配置。 |
| 首购、复购与费率 | 先让一笔静态采购或续费全部失败并全额释放预扣，核对净扣款为零且不占首购。再令后下的正净扣款订单先结算，依次记首购和复购。覆盖三类产品订单、佣金余额消费、费率范围及精度、四舍五入到 0 分、暂停期间的判定和恢复计佣。 |
| 佣金与钱包 | 以推广员身份转入合法金额，核对佣金扣减、钱包单笔入账、独立流水及充值统计。暂停推广后仍可转入既有佣金。验证超额、并发和同请求重放，以及无权租户无法查看其他推广记录。 |
| 权限与购买回归 | 使用相应运营角色执行调额、结案、费率、推广暂停、恢复及重置。只有读取权限或具备其他写权限的账号不能执行对应写操作。客户只能操作自己的订单和分配。保留动态和静态独立开售，以及原钱包、交付和保号续费验收。 |

## 范围外

- 多级分销、现金提现、已结算订单退款后的佣金追扣，归后续产品设计。
- 跨地区换号、批量换号、付费换号、自动恢复租户换号额度，归后续范围评审。共享静态 IP 换号按专项联调结果另行开放。
- 外部支付、在线充值和代理网关计量改造遵循现有产品范围。
