# #40 悟空自定义会话时长验收

2026-11-16 参数对照已执行。**悟空接受 sidtime，可按有限支持推进 #53。** 客户自定义入口由 #53 实现和验收。实际时长、到期和出口分配仍以悟空行为为准。

## 产品边界

文档和商务对接可使用以下口径，客户入口以 #53 的交付状态为准。

> Proxy 对自定义会话时长提供有限支持。网关将同一会话的请求转发到同一个悟空入口。会话的实际时长、到期处理和每次连接的出口 IP 由悟空决定。同一会话重连时，出口 IP 可能变化。

[#36](https://github.com/DuanJinTaoToday/proxy/issues/36) 与 [#53](https://github.com/DuanJinTaoToday/proxy/issues/53) 已按此边界更新。#53 验收参数透传、省略时使用悟空默认行为、同一会话的入口选择和入口不可用时的处理。下文保留上游实际观测和待验证项，供供应商对接使用。

## 供应商资料与历史实测

- 现有[接入文档](../../integrations/wukong-socks5-tunnel.md)引用同事提供的 `3600` 样例。现有资料未提供可核验的供应商契约，需取得单位、默认值、上下限及包含关系、非法值处理、计时起点、续期规则，以及可观测的到期信号。
- 2026-11-10 本机用 `socks5h` 和 `3600` 访问查 IP 服务。固定入口和目标时，同 SID 有两次成功显示相同出口且中间经历一次握手关闭，另一入口的两次成功显示不同出口。历史文档未记录该轮客户端版本。
- [#10 历史记录](../proxy-phase-one/issue-10-cross-host-acceptance.md)中，`3600`、`10`、`1` 均出现成功请求。固定入口下，`10` 的两次成功请求启动时间相隔 27 秒，`1` 的四次成功请求首末启动时间相隔 28 秒。成功只证明当次请求被接受，供应商可能应用了其他时长。2026-11-13 分机验收另用 Ubuntu 网关与 GOST v3.3.3 验证了普通转发和计量。
- 源码基线 `23b3e59`。网关上游 SOCKS5 认证固定拼接九位 SID 和 `-sidtime-3600`，客户侧认证拒绝包含 `-sidtime-` 的用户名。当前可通过网关验收普通接入。下列可变参数用获准客户端直连上游验证。

## 复跑步骤与判据

1. 保持账号、入口、目标和其他用户名字段固定，每组首次连接使用独立九位测试 SID。用 `3600` 建立基线，再只移除 `-sidtime-<值>` 后缀。使用 SOCKS5 远端解析目标，禁用代理绕过与隐式重试，每次新建连接。记录省略是否成功及可观测的默认时长。
2. 取得供应商范围后，分别使用最小值、最大值、相邻越界值、0、负数及非数字。逐例记录接受、拒绝或回退和失败阶段。若异常值通过认证，只有可观测的会话状态或可对照的实际到期时间才能区分回退、截断和实际生效。用两个不同有效值核对时间差与声明单位。
3. 确定一个预算内可完整观察的有效时长 T，并为独立的对照 SID 和重连 SID 分别记录首次 SOCKS5 CONNECT 成功时刻。对照组在 T 内保持原连接、避免新建连接，重连组在 T 内新建一次同 SID 连接。两组分别于各自首次 CONNECT 后 T 刚过时重连，且重连组此时距离上次重连小于 T。用供应商会话状态、会话代次或明确到期信号判断重连是否延长有效期。为区分认证起算和 CONNECT 成功起算，若可取得足够粒度的状态并且预算允许，另用新 SID 对照一次延迟 CONNECT。无可靠到期信号时，结果标为未验证。
4. 在上述时序实验中保留首条连接，跨到期点在同一 TCP/TLS 连接上继续双向交换短消息并核对目标记录。控制空闲超时，并以连接标识确认客户端未透明重连。出口 IP 只记录为脱敏的相同或不同。区分入口 TCP、SOCKS5 方法协商、认证、CONNECT、TLS、目标响应和已建立连接读写失败。
5. 逐次记录带时区的时间、相对时长、客户端或网关版本、来源环境、入口、目标、SID 别名、参数、预期、结果、失败阶段和字节数。只保留状态码、脱敏会话标识、响应长度和出口比较结果。凭据通过获准来源注入，原始用户名、密码和响应正文不进入日志或验收记录。

6. 用独立 SID 组对照有效期内同 SID 省略时长和显式改填另一有效值，再在确认到期后用同 SID 改填。记录悟空是否接受、拒绝或改变会话。这组用例用于补充认识供应商行为。
