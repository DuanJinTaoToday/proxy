# Proxy Console 前端设计与实施计划

一套 Vue 应用承载官网、用户控制台和运营控制台。三个入口共用 Element Plus、设计 token 和中英文语言设置，分别拥有导航和页面布局。本文以首版产品范围为依据，从零定义骨架。开发约定见 [Proxy Console 前端规范](../../standards/proxy-console-frontend.md)。

## 视觉与技术方案

官网首页采用定稿原型 D。首屏使用深色点阵地图和轮换标题，主操作为白色「免费注册」按钮。下方依次展示两类商品、SOCKS5 接入、用量与子账号管理示例、常见问题和注册入口。

定稿提交为 `d6349bff0726cd82923e516c6c3234315ce5715c`。按[原型预览说明](../../../prototypes/console/README.md)启动后，打开 `/home.html?variant=D` 查看地图首屏。评审时可追加 `&hero=globe` 查看地球版本。正式首页默认使用地图。

用户控制台采用深绿侧栏、浅灰画布和白色内容面，突出余额、到期时间、接入配置和购买确认。运营控制台沿用同一主题，使用更紧凑的筛选和表格。控制台主操作用实心深绿按钮，薄荷绿作强调，次级操作用描边或文字按钮。卡片按任务分区，保留适度留白和明确的状态文字。

参考 711Proxy 的任务分组、资源数量与相邻操作、接入配置与结果并排，以及静态 IP 的筛选和批量操作。Proxy 的仪表板围绕两类商品与钱包组织，视觉基线采用独立的浅色主题。 [711Proxy 仪表板](https://dashboard.711proxy.com/zh-CN) · [动态代理接入](https://dashboard.711proxy.com/zh-CN/residential-regular-gb) · [静态 IP 列表](https://dashboard.711proxy.com/zh-CN/static-residential-proxies)

使用 Vue 3、TypeScript、Vite、Vue Router、Element Plus 和 Vue I18n。按路由懒加载。一套 `dist` 同域部署，HTTPS 入口支持前端深链回退并将业务 API 转发给 `proxy-control`。用集中封装的 `fetch` 接口层对接控制面。需要共享服务端缓存的切片引入 TanStack Vue Query。使用组件库的基础控件和主题变量，业务组件按模块封装。

## 导航与语言路由

三个入口右上角顺序统一为「通知铃铛 → 语言切换 → 用户入口」。游客看到登录与注册，使用通知入口时引导登录。已登录用户看到当前账号菜单，铃铛展示当前账号的通知。

### 官网

`/` 默认进入 `/zh-CN/`。英文首页为 `/en/`。以下表格中的 `:locale` 只接受 `zh-CN` 和 `en`。官网使用顶部导航。

| 菜单 | 页面 | 路由 |
| --- | --- | --- |
| 首页 | 官网首页 | `/:locale/` |
| 代理产品 | 动态住宅代理、静态住宅 IP | `/:locale/products/dynamic`、`/:locale/products/static` |
| 价格 | 动态住宅代理报价、静态住宅 IP 报价 | `/:locale/pricing/dynamic`、`/:locale/pricing/static` |
| 使用教程 | SOCKS5 快速接入 | `/:locale/docs/socks5` |
| 用户入口 | 登录、注册 | `/:locale/login`、`/:locale/register` |

游客可浏览报价。登录回到原购买流程时保留商品规格和数量，由确认页重新查询价格及库存。未开售商品保留介绍并显示「暂未开放购买」。

正式首页的价格和开售状态来自公开商品接口。SOCKS5 命令、出口响应和用量图表使用明确标注的示例。登录、注册和购买通过正式路由进入相应流程。

### 用户控制台

`/console` 默认进入仪表板。侧栏按「代理」「管理」分组。商品内的页签有独立路由，支持直接访问、刷新和浏览器后退。

| 分区 | 一级菜单 | 默认页与子页 | 路由 |
| --- | --- | --- | --- |
| — | 仪表板 | 仪表板 | `/console` |
| 代理 | 动态住宅代理-GB | 代理设置、价格、数据统计、使用教程 | `/console/dynamic/{setup,pricing,usage,guide}` |
| 代理 | 静态住宅代理 | IP 列表、价格、使用教程 | `/console/static/{ips,pricing,guide}` |
| 代理 | 代理子账号 | 子账号列表 | `/console/sub-accounts` |
| 管理 | 钱包 | 钱包余额与流水 | `/console/wallet` |
| 管理 | 我的账户 | 账户信息、订单记录 | `/console/account/{profile,orders}` |

仪表板首屏展示产品快捷购买与钱包余额。两类商品入口旁分别展示可用流量和可用 IP 数量。下方展示动态代理近 7 天消耗图表。低余额或即将到期时，显示提醒和对应处理入口。通过侧栏管理代理子账号。静态续费和 TXT 导出从 IP 列表发起。

### 运营控制台

`/ops` 默认进入租户列表。使用独立的侧栏菜单。

| 一级菜单 | 默认页与子页 | 路由 |
| --- | --- | --- |
| 租户管理 | 按手机号或主账号名查找租户。由租户详情进入充值、钱包流水和查单。 | `/ops/tenants`、`/ops/tenants/:tenantId` |
| 商品管理 | 默认进入动态住宅代理-GB，管理流量套餐和开售状态。静态住宅代理单独管理开售。 | `/ops/products/{dynamic,static}` |
| 订单处理 | 待处理的静态 IP 购买与续费订单。 | `/ops/orders` |

两个控制台保持固定 URL，并从浏览器读取语言偏好。三个入口使用同一语言选择器。中文和英文都覆盖菜单、交互、提示以及教程。官网以当前 URL 的语言为准，切换时保持对应页面与查询参数。控制台切换时保持路由、筛选和当前操作状态。

## 实施计划与验收

### 第一阶段 · 可运行骨架

1. 建立可独立安装、启动、类型检查和构建的前端工程。接入 Vue Router，完成三套路由布局、默认入口、语言路由、未找到页和静态产物的深链回退验证。
2. 按前端规范放置装配、路由页面、模块、API、共享组件和样式。随使用创建目录。登录、用户、订单和设置的边界先由规范定义。
3. 接入 Element Plus 和默认主题。用官网首页和控制台基础页验证按钮、菜单、卡片、提示与页面标题。共用顶栏和空状态提供可复用的基础版本，有真实业务后再接入通知列表和账号动作。
4. 接入中英文资源、文档语言、Element Plus locale 和浏览器语言偏好。使用真实中文和英文按钮及标题检查布局。

| 验收项 | 操作与预期 |
| --- | --- |
| 运行与构建 | 在 `apps/proxy-console` 执行 `npm ci`，用 `npm run dev` 启动。运行 `npm run typecheck` 和 `npm run build`，再用 `npm run preview` 打开构建产物并刷新深链。 |
| 路由 | 访问 `/` 到中文首页。直接打开英文首页和两个控制台入口，各自显示对应布局。未知路径显示未找到页。 |
| 目录和复用 | 检查页面和装配文件位置，基础控件直接来自 Element Plus。跨入口共用同一个顶栏组件和同一组主题 token。 |
| 样式和双语 | 在约 390 px、1280 px 宽度检查两种语言。文本和操作可读，横向溢出受控。切换并刷新后控制台语言保留，公开首页切换到对应语言 URL。 |

本阶段交付的是路由与界面基础。认证保护、业务数据、图表、下单、充值和通知服务由各自切片交付。完整菜单和页签随目标页面启用。

### 第二阶段 · 三张代表页

完成官网商品区、用户仪表板、静态 IP 列表的视觉评审。三页覆盖商品卡、余额卡、图表容器和批量操作。中文和英文使用同一套组件。用未开售、零余额、低余额、临近到期、无数据、无结果和长英文提示检验版式。评审通过后固化字号、间距、控件密度和需要复用的业务组件。

### 第三阶段 · 第一条业务切片

从公开动态报价进入登录或注册。登录后恢复购买意图，重查报价。余额不足时显示差额。运营从租户详情确认充值，客户重新确认购买。从订单、钱包流水和流量余额核对同一次交易。覆盖未授权访问、双租户隔离、重复提交和结果未知后的原请求重试。

### 第四阶段 · 商品能力与开售验收

动态住宅验证子账号、SOCKS5 接入、近 7 天消耗、用量筛选和 CSV。静态住宅验证库存及价格复核、部分交付、退款、单条复制、TXT 导出和批量续费逐项结果。两类商品独立验收开售。涉及真实控制面和供应商的验收按首版 Spec 和项目 verify 执行。 [首版 Spec](proxy-first-release-spec.md) · [项目 verify](../../../.agents/skills/verify/SKILL.md)
