2026-11-16 上海时间。控制面基线 `b6fbe2d`，皇冠测试系统 `test.ipcrown.com`，使用经确认与正式账户隔离的测试额度。控制台筛选使用本分支。静态商品开关仅在本地测试库短暂开启，验收后恢复关闭。 [#52](https://github.com/DuanJinTaoToday/proxy/issues/52) · [首版 Spec](proxy-first-release-spec.md)

## 皇冠实测

- 购买复用 #48 的节点 3、`yp1` 单 IP 订单。平台预扣和实结均为 5,000 分，皇冠测试额度扣减 50.00。原采购明细和接入信息一致，原拨测经 SOCKS5 返回 HTTP 200。[#48 购买证据](https://github.com/DuanJinTaoToday/proxy/issues/48#issuecomment-6908432379)
- 单项续费复用 #48/#49 的分配。批量续费复用 #39 的两条已交付明细。在 #48/#49 数据库的隔离副本中为 #39 建立对应的待核实订单和测试预扣，再由运营核实接口按皇冠原主单读回两条分配。导入期间皇冠额度维持 1,700.00。本轮新增皇冠采购为零。[#39 原批次与 #49 单项记录](issue-39-ipcrown-contract.md)
- 两笔都从平台取得确认报价并提交 `yp1` 续费。逐项比对了皇冠原主单、明细 ID、IP 与到期时间，平台分配与皇冠查单一致。每笔平台订单仅有一条改变可用余额的流水，待结算均为零。原请求重放返回原订单，钱包与皇冠余额均无变化。

| --- | ---: | --- | --- | ---: | --- |

续费后三条原 IP 均使用控制台授权配置，经 SOCKS5 访问同一 HTTPS 拨测目标并返回 HTTP 200。皇冠扣费以账号的测试额度差额核对，皇冠查单无逐项续费扣费字段。

## 受控异常回归

使用 PostgreSQL 和可控供应商响应执行 `TestStaticPurchaseAndIndependentSales` 及 `TestStaticRenewalPriceRecheckAndMixedSettlement`。验证缺货、价变、部分交付、待核实、预扣释放和迟到结果不重复入账。新增覆盖在续费待确认期间到期，配置接口拒绝读取；查单确认保号后，同一分配恢复可取。运营队列和关单测试通过受控时间推进验收。

## #50 静态侧证据

- 皇冠真实目录查询返回 80 条规格，其中 44 条有库存。节点 3 的 `yp1` 报价为 ¥50.00／IP、30 天，当次可购 143 个。官网和租户购买页共用目录，按地区、类型、租期及有库存组合筛选。规格列表显示对应单价和可购量，现价与库存以确认报价为准。
- 账户概览从真实分配读取 3 个可用静态 IP。仅开启静态商品时显示购买静态 IP 快捷入口，动态购买仍关闭；关闭静态后概览返回的购买能力随之关闭。使用真实分配并在隔离副本临时将一条到期时间移到两天内，确认概览出现一条提醒，随后恢复到期时间。
- Edge 1280 px 和 320 px 通过官网目录筛选、库存、单价、账户概览和购买入口检查。租户隔离、过期分配不计入概览和跨页面提醒去重由控制面集成用例覆盖。[#50](https://github.com/DuanJinTaoToday/proxy/issues/50)
