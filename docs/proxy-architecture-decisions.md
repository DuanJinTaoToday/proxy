# 一期架构决策与取舍

沿用[一期方案](multi-tenant-proxy-architecture.md)的三个部署单元。以下默认方案供评审，表中待定项需要产品或工程确认后再形成实施承诺。

## 会上优先决定

| 决策 | 一期建议 | 需要确认 |
| --- | --- | --- |
| **首批客户与访问范围** | 支持 TCP CONNECT，接一家第三方 SOCKS5，保留可替换的上游适配接口。按租户限制目标与端口，确保目标实际解析地址符合策略。 | 首批客户端、第三方并发与带宽上限、DNS 由谁解析和执行目标地址策略。若上游解析且无法执行 IP 规则，受限目标使用经验证的 IP 拨号。 |
| **公网接入** | 固定域名解析到三台 `proxy-gateway` 的公网 IP，客户端直接发起 SOCKS5 TCP 连接。 | 确认 DNS TTL、是否启用按健康状态更新记录、首批客户端的地址选择与重试行为，以及每台网关的公网带宽与费用。 |
| **第三方上游路由** | 建议三台网关共享 12 台上游。CONNECT 时按健康状态和容量选择节点，会话建立后固定使用所选节点。 | 确认各上游的并发限制和带宽口径，按上游汇总三台网关的使用量并留出余量。验证出口 IP 固定需求是否限制跨节点切换。 |
| **凭据安全与吊销** | 验证 RFC 1929 的 Key 字段映射与客户端兼容性，存储校验摘要并隐藏日志凭据。内网或受保护通道先试点。缓存未命中或过期且 Control 不可用时，拒绝新连接。 | 公网接入是否要求隧道或其他传输保护。确认缓存最大时效、吊销生效时限和已有会话处置。目标站点的 HTTPS 不会保护此前的 SOCKS5 认证。 [RFC 1929](https://www.rfc-editor.org/rfc/rfc1929.html) |
| **扣费与超额** | 先按字节小批量结算，余额触线后限制新连接。单机按连接或租户限速只能约束本实例。 | 计费单位、费率及舍入，允许多少超额，存量会话是否立即停用。如果需要严格总额度，先实现跨实例额度预留或租约，处理租约过期、重复申请和额度回收。 |
| **计量耐久与故障策略** | 用量异步投递，控制面按事件标识幂等处理。把可重放边界设在可靠写入之后。队列异常时以有界积压保护网关。 | 网关异常退出允许丢多少尚未持久化的用量，积压耗尽时拒绝新连接还是停止在途会话。若要求补账，明确持久化检查点、事件重放及对账来源。 |
| **一期容量承诺** | 先测 `5 Gbps + 10 万并发会话`，再验证 `15 Gbps + 50 万并发会话`。两项均为待测目标。 | 生产流量比例、平均连接时长、连接峰值、延迟和错误率预算，第三方出口能否支持对应负载。 [容量与压测方案](proxy-capacity-benchmark.md) |

## 工程基线

- **接口。** 控制台通过 HTTPS 管理 API 操作。网关通过内部认证与策略接口获取租户上下文，通过消息队列异步发布用量。转发循环只执行本地检查、转发和计量。
- **存储。** 建议用 PostgreSQL 保存身份、凭据、策略、用量和账务。余额变更与账务流水放在同一事务内。消息队列选团队可运维的方案，验收持久化确认、重投与积压能力。缓存先从网关进程内的有界缓存做起，观察命中率和失效传播后再决定是否引入共享缓存。
- **流量限制。** 如果一期要求精确的字节级限速或额度，应把它加入生产基线一起测试。靠周期用量上报只能做到事后结算。按会话做限速、跨网关做租户级限制是两项独立能力。
- **计划下线。** 从 DNS 移除待维护网关的地址，观察仍命中旧地址的新连接。达到运维约定的排空起点后停止新接入，等待现有会话结束或到达排空期限，再提交末批用量。网关突发故障时，已有会话需要客户端重连。验证 DNS 变更后的解析缓存、连接失败超时以及客户端是否尝试其他地址。 [DNS 缓存与解析](https://www.rfc-editor.org/rfc/rfc1035.html#section-2.1)

业务状态及异常路径见[领域模型与状态机](proxy-domain-model.md)。支付方式和传输保护选定后再补正式决策记录。
